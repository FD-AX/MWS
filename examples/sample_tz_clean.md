# ТЗ: Поток SRC_RADIO_CM и витрина DM_CELL_CONFIG_DAILY

## 1. Общие сведения

Разработать поток загрузки конфигурационных параметров ячеек радиосети из источника SRC_RADIO_CM и суточную витрину DM_CELL_CONFIG_DAILY. Владелец: команда NET. Потребители: отдел планирования сети (отчёт «Конфигурация ячеек», еженедельный).

## 2. Источник данных

Файлы CSV на SFTP sftp://oss-export/cm/, маска cm_cells_YYYYMMDD_HH24.csv, кодировка UTF-8, разделитель «;». Доступ: технологическая учётная запись svc_net_etl (выдаётся через заявку INFRA-ACCESS). Полный перечень полей источника: CELL_ID, SITE_ID, BAND, TX_POWER_DBM, TILT_DEG, AZIMUTH_DEG, UPDATED_AT. Других полей в выгрузке нет.

## 3. Структура целевых таблиц

Витрина DM_CELL_CONFIG_DAILY, гранулярность: одна строка на ячейку на дату среза. Первичный ключ: (CELL_ID, SNAPSHOT_DATE).

| Поле | Тип | Источник / правило |
|---|---|---|
| CELL_ID | VARCHAR(64) | SRC_RADIO_CM.CELL_ID |
| SITE_ID | VARCHAR(64) | SRC_RADIO_CM.SITE_ID |
| BAND | VARCHAR(16) | SRC_RADIO_CM.BAND |
| TX_POWER_DBM | DECIMAL(5,1) | SRC_RADIO_CM.TX_POWER_DBM |
| TILT_DEG | DECIMAL(4,1) | SRC_RADIO_CM.TILT_DEG |
| AZIMUTH_DEG | DECIMAL(5,1) | SRC_RADIO_CM.AZIMUTH_DEG |
| SNAPSHOT_DATE | DATE | дата из имени файла |

## 4. Правила трансформации

Загружается последний по UPDATED_AT срез за дату: при нескольких записях одной ячейки за дату выживает запись с максимальным UPDATED_AT; при равенстве UPDATED_AT — запись из более позднего файла. Значения NULL в TX_POWER_DBM, TILT_DEG, AZIMUTH_DEG сохраняются как NULL (в расчётах не участвуют, в отчёте отображаются как «н/д»). Записи с пустым CELL_ID отбраковываются в таблицу ошибок ERR_CELL_CONFIG с кодом EMPTY_KEY.

## 5. Регламент загрузки

Инкремент по дате в имени файла: загружаются файлы за даты, отсутствующие в витрине, плюс повторная обработка окна в 3 календарных дня назад (файлы за эти даты перезагружаются полностью с заменой партиции). Файлы, пришедшие позже окна, загружаются вручную по заявке. Удаление ячейки в источнике отражается отсутствием записи в новом срезе; исторические срезы не изменяются.

Запуск ежедневно в 06:00 МСК. Данные за дату D доступны потребителям не позднее 08:00 МСК дня D+1. При недоступности SFTP выполняется 3 повтора с интервалом 30 минут, после чего формируется алерт в канал NET-ALERTS.

## 6. Контроль качества

После загрузки сверяется количество строк витрины с количеством строк файла за вычетом отбракованных; расхождение более 0 строк — алерт. Контроль полноты: наличие файла за каждую дату; отсутствие файла до 07:00 МСК — алерт. Ожидаемый объём: ~200 тыс. строк в сутки, хранение — 400 дней, партиционирование по SNAPSHOT_DATE.

## 7. Прочее

Термин «ячейка» используется во всём документе единообразно и соответствует полю CELL_ID источника.
