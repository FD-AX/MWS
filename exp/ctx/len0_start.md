# Реестр витрин данных

## Описание витрины-агрегата TABLE_AGG_TRAFFIC_REGION

### Общие сведения

Ежемесячный агрегат интернет-трафика абонентов по регионам и типам сети.

### Бизнес-требования

Название таблицы: TABLE_AGG_TRAFFIC_REGION

Кластер: CLUSTER

Схема: SCHEMA_CDM_NETS

### Системы-источники

DPI_System — платформа учёта интернет-трафика абонентов.

| Схема | Таблица | Описание |
|---|---|---|
| SCHEMA_RAW | TABLE_DPI_RAW_PS | Необработанные записи об интернет-сессиях |
| SCHEMA_DIC | TABLE_REGION_REF | Справочник регионов |

Структура TABLE_DPI_RAW_PS:

| Поле | Тип данных | Описание |
|---|---|---|
| FIELD_REGION | string | Код региона |
| FIELD_BIZ_DATE | date | Бизнес-дата сессии |
| FIELD_HOUR | int | Часовая партиция |
| FIELD_IMSI | bigint | IMSI абонента |
| FIELD_TIME_STAMP | timestamp | Время окончания сессии (UTC) |
| FIELD_BYTES_UL | bigint | Объём исходящего трафика, байты |
| FIELD_BYTES_DL | bigint | Объём входящего трафика, байты |
| FIELD_RAT | string | Тип сети (2G, 3G и т. д.) |
| FIELD_LOAD_ID | bigint | Идентификатор файла загрузки |

Структура TABLE_REGION_REF:

| Поле | Тип данных | Описание |
|---|---|---|
| FIELD_REGION | string | Код региона |
| FIELD_REGION_NAME | string | Название региона |

### Структура данных CDM

Таблица: TABLE_AGG_TRAFFIC_REGION

| Поле | Тип данных | Описание | Правило |
|---|---|---|---|
| FIELD_BIZ_DATE | date | Бизнес-дата: 1-е число месяца агрегации | партиция |
| FIELD_REGION_NAME | string | Название региона | из TABLE_REGION_REF по FIELD_REGION |
| FIELD_RAT_NAME | string | Тип сети (2G, 3G, 4G, UNKNOWN) | из FIELD_RAT |
| FIELD_TRAFFIC_GB | decimal(18,3) | Суммарный трафик за месяц, ГБ | (sum(FIELD_BYTES_UL) + sum(FIELD_BYTES_DL)) / 1024^3 |
| FIELD_USERS_CNT | bigint | Число уникальных абонентов | count(distinct FIELD_IMSI) |
| FIELD_PROC_TS | timestamp | Время формирования строки | метка запуска DAG_AGG_TRAFFIC |

Ключ таблицы: (FIELD_BIZ_DATE, FIELD_REGION_NAME, FIELD_RAT_NAME).

### Алгоритм расчёта

Шаг 1. Отбор данных
Из TABLE_DPI_RAW_PS берутся все записи с FIELD_BIZ_DATE внутри календарного месяца агрегации.

Шаг 2. Фильтрация
Записи с нулевым суммарным объёмом (FIELD_BYTES_UL + FIELD_BYTES_DL = 0) исключаются из расчёта; количество исключённых записей пишется в журнал TABLE_AGG_LOAD_LOG.

Шаг 3. Обработка пропусков
Записи с пустым FIELD_REGION отбрасываются в TABLE_AGG_LOAD_LOG с кодом EMPTY_REGION. Полный перечень кодов отбраковки приведён в разделе 12.

Шаг 5. Определение региона
Он определяется через справочник TABLE_REGION_REF; коды, отсутствующие в справочнике, учитываются в категории NO_REGION.

Шаг 6. Агрегация и запись
Группировка по FIELD_BIZ_DATE, FIELD_REGION_NAME, FIELD_RAT_NAME; расчёт FIELD_TRAFFIC_GB и FIELD_USERS_CNT; полная перезапись партиции месяца (без upsert).

### Регламент

Запуск: ежемесячно, 2-го числа в 03:00 UTC, оркестрация DAG_AGG_TRAFFIC.

Срок готовности: данные за месяц публикуются оперативно после расчёта.

Повторный расчёт месяца выполняется тем же DAG с параметром месяца; партиция перезаписывается целиком.

### Требования к агрегату

| Требование | Значение |
|---|---|
| Период агрегации | Календарный месяц |
| Способ обновления | Полная перезапись партиции месяца (без upsert) |
| Время запуска | 2-е число, 03:00 МСК |
| Часовой пояс | UTC |
| Поле партиционирования | FIELD_PART_DATE |
| Ретеншен витрины | 24 месяца |

### Контроль качества

После записи партиции выполняются проверки:

- сверка суммы байтов витрины с источником: существенных расхождений быть не должно;
- контроль отброшенных записей: доля EMPTY_REGION и NO_REGION не более 1% от объёма месяца, иначе алерт в LINK_ALERT_CHANNEL;
- проверка наличия всех регионов справочника в партиции.

Результаты проверок пишутся в TABLE_AGG_LOG_LOAD.
