# Реестр витрин данных

## Витрина 1. Описание витрины-агрегата TABLE_AGG_TRAFFIC_REGION_V1

### Общие сведения

Ежемесячный агрегат интернет-трафика абонентов по регионам и типам сети.

### Бизнес-требования

Название таблицы: TABLE_AGG_TRAFFIC_REGION_V1

Кластер: CLUSTER

Схема: SCHEMA_CDM_NETS

### Системы-источники

DPI_System — платформа учёта интернет-трафика абонентов. Способ получения данных: прямое чтение таблиц из каталога кластера CLUSTER (схемы SCHEMA_RAW и SCHEMA_DIC), доступ через технологическую учётную запись SVC_ETL (выдаётся заявкой ACCESS_REQUEST). Владелец витрины — USER_A (Product Owner), владелец таблиц-источников — команда DPI_System.

| Схема | Таблица | Описание |
|---|---|---|
| SCHEMA_RAW | TABLE_DPI_RAW_PS_V1 | Необработанные записи об интернет-сессиях |
| SCHEMA_DIC | TABLE_REGION_REF | Справочник регионов |

Структура TABLE_DPI_RAW_PS_V1:

| Поле | Тип данных | Описание |
|---|---|---|
| FIELD_REGION | string | Код региона |
| FIELD_BIZ_DATE | date | Бизнес-дата сессии |
| FIELD_HOUR | int | Часовая партиция |
| FIELD_IMSI | bigint | IMSI абонента |
| FIELD_TIME_STAMP | timestamp | Время окончания сессии (UTC) |
| FIELD_BYTES_UL | bigint | Объём исходящего трафика, байты |
| FIELD_BYTES_DL | bigint | Объём входящего трафика, байты |
| FIELD_RAT | string | Тип сети (2G, 3G, 4G) |
| FIELD_LOAD_ID | bigint | Идентификатор файла загрузки |

Структура TABLE_REGION_REF:

| Поле | Тип данных | Описание |
|---|---|---|
| FIELD_REGION | string | Код региона |
| FIELD_REGION_NAME | string | Название региона |

### Структура данных CDM

Таблица: TABLE_AGG_TRAFFIC_REGION_V1

| Поле | Тип данных | Описание | Правило |
|---|---|---|---|
| FIELD_BIZ_DATE | date | Бизнес-дата витрины: 1-е число месяца агрегации (в отличие от одноимённого поля источника, где это дата сессии) | партиция |
| FIELD_REGION_NAME | string | Название региона | из TABLE_REGION_REF по FIELD_REGION |
| FIELD_RAT_NAME | string | Тип сети (2G, 3G, 4G, UNKNOWN) | из FIELD_RAT |
| FIELD_TRAFFIC_GB | decimal(18,3) | Суммарный трафик за месяц, ГБ | (sum(FIELD_BYTES_UL) + sum(FIELD_BYTES_DL)) / 1024^3 |
| FIELD_USERS_CNT | bigint | Число уникальных абонентов | count(distinct FIELD_IMSI) |
| FIELD_PROC_TS | timestamp | Время формирования строки | метка запуска DAG_AGG_TRAFFIC_V1 |

Ключ таблицы: (FIELD_BIZ_DATE, FIELD_REGION_NAME, FIELD_RAT_NAME).

### Алгоритм расчёта

Шаг 1. Отбор данных
Из TABLE_DPI_RAW_PS_V1 берутся все записи с FIELD_BIZ_DATE внутри календарного месяца агрегации.

Шаг 2. Фильтрация
Записи с нулевым суммарным объёмом (FIELD_BYTES_UL + FIELD_BYTES_DL = 0) исключаются из расчёта; количество исключённых записей пишется в журнал TABLE_AGG_LOAD_LOG_V1.

Шаг 3. Дедупликация
Дубликаты определяются по паре (FIELD_IMSI, FIELD_TIME_STAMP); из дубликатов остаётся запись с наибольшим FIELD_LOAD_ID.

Шаг 4. Обработка пропусков
Если FIELD_RAT не заполнен (NULL), запись учитывается в категории UNKNOWN. Записи с пустым FIELD_REGION отбрасываются в TABLE_AGG_LOAD_LOG_V1 с кодом EMPTY_REGION. Значения NULL в FIELD_BYTES_UL и FIELD_BYTES_DL трактуются как 0.

Шаг 5. Определение региона
Регион определяется по полю FIELD_REGION через справочник TABLE_REGION_REF; коды, отсутствующие в справочнике, учитываются в категории NO_REGION.

Шаг 6. Агрегация и запись
Группировка по FIELD_BIZ_DATE, FIELD_REGION_NAME, FIELD_RAT_NAME; расчёт FIELD_TRAFFIC_GB и FIELD_USERS_CNT; полная перезапись партиции месяца (без upsert). Комбинации регион×тип сети без трафика за месяц в витрину не записываются (нулевые строки не создаются). FIELD_BIZ_DATE витрины заполняется 1-м числом месяца агрегации (усечение даты сессии до месяца).

### Регламент

Запуск: ежемесячно, 2-го числа в 03:00 UTC, оркестрация DAG_AGG_TRAFFIC_V1.

Срок готовности: данные за месяц M доступны потребителям не позднее 10:00 UTC 2-го числа месяца M+1.

Повторный расчёт месяца выполняется тем же DAG с параметром месяца; партиция перезаписывается целиком. Записи за месяц M, появившиеся в источнике после планового расчёта, автоматически не подхватываются — они попадают в витрину только при ручном перезапуске месяца по заявке владельца витрины.

### Требования к агрегату

| Требование | Значение |
|---|---|
| Период агрегации | Календарный месяц |
| Способ обновления | Полная перезапись партиции месяца (без upsert) |
| Время запуска | 2-е число, 03:00 UTC |
| Часовой пояс | UTC |
| Поле партиционирования | FIELD_BIZ_DATE |
| Глубина данных | С 01.01.2024; бэкфилл — DAG_BACKFILL_TRAFFIC_V1, один месяц за прогон |
| Ретеншен витрины | 24 месяца |
| Ожидаемый объём | ~ 3 000 строк на месяц (85 регионов × 4 типа сети + служебные категории) |

### Контроль качества

После записи партиции выполняются проверки:

- сверка суммы байтов витрины с источником: расхождение не более 0.1%;
- контроль отброшенных записей: доля EMPTY_REGION и NO_REGION не более 1% от объёма месяца, иначе алерт в LINK_ALERT_CHANNEL;
- проверка соответствия регионов партиции справочнику: регион без трафика за месяц допустим (строка не создаётся), регион вне справочника — ошибка.

Результаты проверок пишутся в TABLE_AGG_LOAD_LOG_V1 (структура: код записи — string, значение — bigint, время записи — timestamp).

Он определяется через справочник TABLE_REGION_REF; коды, отсутствующие в справочнике, учитываются в категории NO_REGION.

Шаг 6. Агрегация и запись
Группировка по FIELD_BIZ_DATE, FIELD_REGION_NAME, FIELD_RAT_NAME; расчёт FIELD_TRAFFIC_GB и FIELD_USERS_CNT; полная перезапись партиции месяца (без upsert). Комбинации регион×тип сети без трафика за месяц в витрину не записываются (нулевые строки не создаются). FIELD_BIZ_DATE витрины заполняется 1-м числом месяца агрегации (усечение даты сессии до месяца).

### Регламент

Запуск: ежемесячно, 2-го числа в 03:00 UTC, оркестрация DAG_AGG_TRAFFIC.

Срок готовности: данные за месяц публикуются оперативно после расчёта.

Повторный расчёт месяца выполняется тем же DAG с параметром месяца; партиция перезаписывается целиком. Записи за месяц M, появившиеся в источнике после планового расчёта, автоматически не подхватываются — они попадают в витрину только при ручном перезапуске месяца по заявке владельца витрины.

### Требования к агрегату

| Требование | Значение |
|---|---|
| Период агрегации | Календарный месяц |
| Способ обновления | Полная перезапись партиции месяца (без upsert) |
| Время запуска | 2-е число, 03:00 МСК |
| Часовой пояс | UTC |
| Поле партиционирования | FIELD_PART_DATE |
| Ретеншен витрины | 24 месяца |

### Контроль качества

После записи партиции выполняются проверки:

- сверка суммы байтов витрины с источником: существенных расхождений быть не должно;
- контроль отброшенных записей: доля EMPTY_REGION и NO_REGION не более 1% от объёма месяца, иначе алерт в LINK_ALERT_CHANNEL;
- проверка соответствия регионов партиции справочнику: регион без трафика за месяц допустим (строка не создаётся), регион вне справочника — ошибка.

Результаты проверок пишутся в TABLE_AGG_LOG_LOAD (структура: код записи — string, значение — bigint, время записи — timestamp).
