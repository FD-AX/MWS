# Целевая архитектура решения (черновик 2026-09-03, ветка `arch/compose-stack`)

Каждое решение ниже привязано к эксперименту из [experiments/](experiments/README.md):
без строки бенча архитектурное решение не принимается (правило проекта).

## 0. Принципы, которые доказаны цифрами

| Принцип | Доказательство |
|---|---|
| **Модель — конфиг, не код.** Любой OpenAI-совместимый эндпоинт: облако, vLLM, ollama, внутренний API заказчика (`TZR_BASE_URL`). | Ночная лестница: тот же конвейер на Qwen2.5-14B и GPT-5.5 (NIGHT_REPORT) |
| **Детерминированное ядро не зависит от модели** и даёт гарантированный пол: шаблон, граф сущностей, языковые паттерны. | EXP-13: v1g F-класс 6/6, easy 8/9, **шум 0** на любой базе |
| **Генерация отделена от фильтрации**, но фильтр не вправе резать требования кейсодателя. | EXP-13: критик ставил 0.0 верным MISSING по Data Catalog / Kafka / фильтрам → EXP-14 «защищённые слоты» |
| **Ансамбль измерений неоднозначности**: сэмплирование (v2e) и логит-зонд (v2l) ловят разные классы. | EXP-13: v2l B-класс 9/9, единственный ловит анафору; v2e лучший на doc3 (14/16) |
| **Ничего не теряем**: очередь, at-least-once, идемпотентность, ретраи с jitter. | EXP-10/11: пустые ответы модели роняли прогон; EXP-13: 10/27 слотов терялись молча → добор |
| **Качество — это бенч, а не мнение**: любая смена модели/промпта = канарейка → бенч → строка в таблице. | experiments/README.md (14 экспериментов, CHANGELOG синтетики it1–it6) |

  (позже)   └──────────┘   GET /reviews/{id} ◀───────────────│ (FastAPI) │                          │

                                                                   │ normalize                ┌───────────┐
                                                             ┌─────▼─────┐                    │  worker   │──▶ results (json/md)

                                                             │ (FastAPI) │                    └─────┬─────┘

## 2. Поток данных и семантика надёжности

1. `POST /reviews` (multipart-файл или `text`) → `docs.normalize` → markdown + `doc_hash` →
   сообщение `{job_id, doc_hash, config_hash, text}` в `review.jobs` (persistent, publisher confirm) → `202 {job_id}`.
2. `worker`: `prefetch=1`; `review(text, rubric, llm, …)` с таймерами по проходам; результат пишется в `results/<job_id>.json|md`;
   **ack только после записи**. Исключение → повтор ×3 с jitter (внутри LLM-клиента) → `nack` → DLQ `review.dead` + метрика.
3. `GET /reviews/{job_id}` → `queued | running | done | failed` + отчёт (светофор, coverage чеклиста, находки по разделам, свёрнутая стилистика).
4. Идемпотентность: `(doc_hash, config_hash)` → готовый результат возвращается без повторного прогона.

Метрики (prometheus_client): `tzr_reviews_total{status}`, `tzr_review_seconds{pass}`, `tzr_llm_calls_total{backend,model,pass}`,
`tzr_llm_tokens_total{kind}`, `tzr_findings_total{class,severity,pass}`, `tzr_checklist_status_total{slot,status}`,
`tzr_unknown_slots` (алерт при > 0), `tzr_dlq_total`, `tzr_bench_recall{variant,target,class}`.

## 4. Прод-конвейер на gpt-oss-120b (по матрице m4, [experiments/PROTOCOL.md](experiments/PROTOCOL.md))

Общее ядро всех вариантов: детерминированный слой (шаблон МТС, языковые паттерны, пустые разделы) → граф сущностей H1
(+ ссылки на разделы по номеру и по имени) → чеклист 27 слотов с применимостью до модели (NA без вызова), добором и раздельными
батчами → документ-уровень → взгляд разработчика → фильтр вопросов о заглушках → верификация цитат с **переанкориванием**
составных цитат → критик с защищёнными официальными слотами. Транспорт к vLLM — потоковый; зонд неоднозначности —
Монте-Карло (логиты у reasoning-модели не читаются, EXP-19).

| Вариант | Состав сверх ядра | Σ/49 (×2, медиана) | doc3 | шум@clean | precision (слепая) | Статус |
|---|---|---|---|---|---|---|
| v2g | — | 38 | 13 | 9 | 83 % | базовая линия |
| **v2x** | + общие слоты (ORD/REF-02/HIS/TZ) | 40.5 | 15 | 10 | **85 %** | **прод-кандидат** (`TZR_RUBRIC_EXTRA=1`) |
| v2s | + зонд Монте-Карло | 42 | 15 | 13 | 80 % | альтернатива: v3official 13/13 ×2 |
| v2f | + слоты + зонд + энтропия | 44.5 | 16 | 12.5 | 63 % | после EXP-21 (канонизация энтропии) |
| v2q | + сверка величин между разделами | EXP-20 | | | | идёт 05.09 |

Финальный выбор — после EXP-21/22 по критерию протокола (precision ≥ 95 % не достигнута ни одним вариантом на 05.09 07:00;
ближайший — v2x 85 %, следующие рычаги — NA-правила v2 и канонизация энтропии). Консенсус двух прогонов остаётся опцией
для критичных документов (разброс 120b ±1–2 дефекта на одной конфигурации).

## 5. Чего не делаем и почему

| Не делаем | Почему |
|---|---|
| Triton Inference Server | для LLM нужен TensorRT-LLM-бэкенд (дни настройки), качества не добавляет; vLLM даёт `/metrics`, logprobs и батчинг из коробки |
| Интеграция с Confluence | вне скоупа кейса; вход — текст/markdown/docx/pdf через `docs` |
| Fine-tuning | нет размеченных корректировок разработчиков; вместо этого калибровка промптов и порогов на фабрике синтетики (H11) и голдах МТС |
| «Одна большая модель на всё» | ночная лестница: детерминированные слои дают F/C-классы бесплатно; дорогая модель нужна только в LLM-этажах |
