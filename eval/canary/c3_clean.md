# ТЗ: Поток TABLE_CANARY_C

## Источник данных

Файлы CSV на SFTP-сервере SFTP_HOST_C (доступ: учётная запись SVC_USER_C), каталог /export/c/, маска c_YYYYMMDD.csv, кодировка UTF-8, разделитель «;», первая строка — заголовок. Поля: FIELD_ID (bigint), FIELD_NAME (string), FIELD_SNAPSHOT_DATE (date; всегда равна дате из имени файла — при расхождении строка отбраковывается с кодом DATE_MISMATCH).

## Структура целевых таблиц

Таблица TABLE_CANARY_C: FIELD_ID (bigint, NOT NULL), FIELD_NAME (string, NULLABLE), FIELD_SNAPSHOT_DATE (date, NOT NULL, партиция). Ключ: (FIELD_ID, FIELD_SNAPSHOT_DATE). Хранение: Hive-таблица на кластере CLUSTER, полный путь hdfs://CLUSTER/data/raw/canary_c/, формат Parquet (Snappy), партиция — каталог FIELD_SNAPSHOT_DATE=YYYY-MM-DD. Карточка в Data Catalog: LINK_DC_CANARY_C (источник SFTP — LINK_DC_SFTP_C). Справочники не используются (не применимо). Kafka не используется (не применимо).

## Правила трансформации

Данные переносятся без преобразований. Записи с пустым FIELD_ID отбрасываются в таблицу ошибок ERR_CANARY_C с кодом EMPTY_KEY. Значения NULL в FIELD_NAME сохраняются как NULL. Дубли по ключу (FIELD_ID, FIELD_SNAPSHOT_DATE) внутри файла: остаётся последняя строка файла, остальные отбраковываются с кодом DUP_KEY; между файлами дублей не возникает, так как партиция даты перезаписывается целиком.

## Регламент загрузки

Инкремент по дате из имени файла: при каждом запуске загружаются файлы за даты, отсутствующие в таблице, и безусловно перезагружаются партиции за последние 2 календарных дня (целиком, вместе с соответствующими файлами). Файлы за даты старше 2 дней автоматически не обрабатываются — загрузка по заявке владельцу потока. Запуск ежедневно в 05:00 UTC; данные за дату D доступны не позднее 07:00 UTC дня D+1. При недоступности SFTP — 3 повтора с интервалом 20 минут, затем алерт.

Строки, не прошедшие приведение типов (FIELD_ID не приводится к bigint, FIELD_SNAPSHOT_DATE не парсится как дата), отбраковываются в ERR_CANARY_C с кодом PARSE_ERROR. Структура ERR_CANARY_C: исходная строка файла (string), код ошибки (string), имя файла (string), время обработки (timestamp).

## Контроль качества

Сверка числа строк файла и таблицы с учётом отбракованных, расхождение больше 0 — алерт; контроль наличия файла за каждую дату до 06:00 UTC. Ожидаемый объём — около 50 тысяч строк в день, хранение — 180 дней.
