# Описание витрины-агрегата TABLE_AGG_TRAFFIC_REGION

## Общие сведения

Ежемесячный агрегат интернет-трафика абонентов по регионам и типам сети. Витрина TABLE_AGG_TRAFFIC_REGION хранится в схеме SCHEMA_CDM_NETS кластера CLUSTER и обновляется раз в месяц полной перезаписью партиции месяца. Документ оформлен по шаблону «Потоковые данные/витрины»; разделы, не имеющие содержания для данной витрины, помечены «не применимо».

## Решаемая проблема

Продуктовой аналитике и MVNO-партнёрам нужен согласованный помесячный объём трафика в разрезе регион × тип сети без доступа к сырым записям DPI: сырьё занимает миллиарды строк в месяц, и расчёт региональных сумм по запросу не укладывается в приемлемое время. Витрина закрывает эту потребность одной компактной таблицей на уровне регион × тип сети.

## Продуктовые метрики

- Доля запросов на региональные суммы трафика, закрытых витриной без обращения к сырым таблицам: цель 100% (сейчас 0%).
- Число ad-hoc запросов к TABLE_DPI_RAW_PS от аналитики за региональными суммами: снижение с ~40 до 0 в месяц.

## Заказчики

MVNO Unit X (основной потребитель), продуктовая аналитика NET (владелец — USER_A).

## Нефункциональные требования

| Требование | Значение |
|---|---|
| Длительность расчёта | не более 2 часов на один месяц при полном объёме источника |
| Доступность на чтение | перезапись партиции атомарная: запись во временный каталог и подмена, читатели не видят частично записанную партицию |
| Нагрузка на источник | один проход по партициям месяца TABLE_DPI_RAW_PS, без повторных чтений |

## Системы-источники

DPI_System — платформа учёта интернет-трафика абонентов. Способ получения данных: прямое чтение таблиц из каталога кластера CLUSTER (схемы SCHEMA_RAW и SCHEMA_DIC), доступ через технологическую учётную запись SVC_ETL (выдаётся заявкой ACCESS_REQUEST). Владелец витрины — USER_A (Product Owner), владелец таблиц-источников — команда DPI_System.

Записи в TABLE_DPI_RAW_PS поступают из Kafka-топика TOPIC_DPI_PS на кластере KAFKA_CLUSTER_DPI потоком STREAM_DPI_PS (описан в отдельном документе LINK_DOC_STREAM_DPI_PS); данный документ описывает только витрину и читает уже загруженные таблицы.

## Схема потоков данных

TOPIC_DPI_PS → STREAM_DPI_PS → TABLE_DPI_RAW_PS (SCHEMA_RAW) → DAG_AGG_TRAFFIC → TABLE_AGG_TRAFFIC_REGION (SCHEMA_CDM_NETS); справочник TABLE_REGION_REF подключается на шаге определения региона. Диаграмма: LINK_DIAGRAM_AGG_TRAFFIC.

## Алгоритм обработки потока

Шаг 1. Отбор данных
Из TABLE_DPI_RAW_PS берутся все записи с FIELD_BIZ_DATE внутри календарного месяца агрегации.

Шаг 2. Фильтрация
Значения NULL в FIELD_BYTES_UL и FIELD_BYTES_DL трактуются как 0. Записи с нулевым суммарным объёмом (FIELD_BYTES_UL + FIELD_BYTES_DL = 0) исключаются из расчёта; количество исключённых записей пишется в журнал TABLE_AGG_LOAD_LOG с кодом ZERO_VOLUME.

Шаг 3. Дедупликация
Дубликаты определяются по паре (FIELD_IMSI, FIELD_TIME_STAMP); из дубликатов остаётся запись с наибольшим FIELD_LOAD_ID. При равном FIELD_LOAD_ID остаётся запись с наибольшим FIELD_BYTES_UL + FIELD_BYTES_DL; полностью одинаковые записи эквивалентны, остаётся любая.

Шаг 4. Обработка пропусков
Если FIELD_RAT не заполнен (NULL), запись учитывается в категории UNKNOWN. Записи с пустым FIELD_REGION отбрасываются в TABLE_AGG_LOAD_LOG с кодом EMPTY_REGION. Записи с NULL в FIELD_IMSI или FIELD_TIME_STAMP отбрасываются туда же с кодом EMPTY_KEY. Непустые значения FIELD_RAT вне списка (2G, 3G, 4G) учитываются в категории UNKNOWN.

Шаг 5. Определение региона
Регион определяется по полю FIELD_REGION через справочник TABLE_REGION_REF; коды, отсутствующие в справочнике, учитываются в категории NO_REGION.

Шаг 6. Агрегация и запись
Группировка по месяцу (FIELD_BIZ_DATE источника, усечённая до 1-го числа), FIELD_REGION_NAME, FIELD_RAT_NAME; расчёт FIELD_TRAFFIC_GB и FIELD_USERS_CNT; полная перезапись партиции месяца (без upsert). Комбинации регион×тип сети без трафика за месяц в витрину не записываются (нулевые строки не создаются). FIELD_BIZ_DATE витрины заполняется 1-м числом месяца агрегации (усечение даты сессии до месяца). Партиция HDFS формируется по этому значению: каталог FIELD_BIZ_DATE=<1-е число месяца> внутри пути витрины, один каталог на месяц.

Типовые фильтры
При построении витрины и при выгрузке потребителям применяются стандартные условия: (1) FIELD_BIZ_DATE в границах месяца расчёта; (2) записи с нулевым суммарным трафиком в расчёт не входят (Шаг 2); (3) при выгрузке потребителям по умолчанию исключаются служебные категории NO_REGION и UNKNOWN, они включаются по явному запросу потребителя.

## Регламент

Запуск: ежемесячно, 2-го числа в 03:00 UTC, оркестрация DAG_AGG_TRAFFIC.

Перед расчётом DAG ждёт сигнал готовности всех часовых партиций месяца от STREAM_DPI_PS (сенсор в DAG_AGG_TRAFFIC); если готовность не наступила к 06:00 UTC, в LINK_ALERT_CHANNEL уходит алерт и расчёт не стартует. При сбое шага DAG выполняется 3 повтора с интервалом 20 минут; после исчерпания повторов уходит алерт, партиция не публикуется (остаётся во временном каталоге).

Срок готовности: данные за месяц M доступны потребителям не позднее 10:00 UTC 2-го числа месяца M+1.

Повторный расчёт месяца выполняется тем же DAG с параметром месяца; партиция перезаписывается целиком. Записи за месяц M, появившиеся в источнике после планового расчёта, автоматически не подхватываются — они попадают в витрину только при ручном перезапуске месяца по заявке владельца витрины.

| Требование | Значение |

| Период агрегации | Календарный месяц |

| Время запуска | 2-е число, 03:00 UTC |

## Контроль качества

После записи партиции выполняются проверки:

- сверка суммы байтов: сумма FIELD_BYTES_UL + FIELD_BYTES_DL по записям источника за месяц после шагов 2–4 (фильтрация, дедупликация, отбраковка EMPTY_REGION и EMPTY_KEY) против суммы FIELD_TRAFFIC_GB × 1024^3 по партиции; расхождение не более 0.1%;
- контроль отброшенных записей: доля записей EMPTY_REGION, EMPTY_KEY и NO_REGION от числа записей источника за месяц (после шага 1) не более 1%, иначе алерт в LINK_ALERT_CHANNEL;
- проверка соответствия регионов партиции справочнику: каждое значение FIELD_REGION_NAME, кроме служебной категории NO_REGION, присутствует в TABLE_REGION_REF; регион без трафика за месяц допустим (строка не создаётся).

При нарушении любой проверки партиция не публикуется (остаётся во временном каталоге), в LINK_ALERT_CHANNEL уходит алерт; публикация выполняется вручную после разбора владельцем витрины.

Результаты проверок пишутся в TABLE_AGG_LOAD_LOG (структура журнала — в разделе «Структура данных»).

## DDL

```sql
CREATE TABLE SCHEMA_CDM_NETS.TABLE_AGG_TRAFFIC_REGION (
  FIELD_REGION_NAME string COMMENT 'Название региона',
  FIELD_RAT_NAME string COMMENT 'Тип сети',
  FIELD_TRAFFIC_GB decimal(18,3) COMMENT 'Суммарный трафик за месяц, ГБ',
  FIELD_USERS_CNT bigint COMMENT 'Число уникальных абонентов',
  FIELD_PROC_TS timestamp COMMENT 'Время формирования строки'
)
PARTITIONED BY (FIELD_BIZ_DATE date)
STORED AS PARQUET;
```

## FAQ

**Почему сумма FIELD_USERS_CNT по всем регионам больше числа уникальных абонентов сети?** FIELD_USERS_CNT считается в каждой строке независимо: абонент с трафиком в двух регионах за месяц учитывается в обеих строках. Для числа уникальных абонентов сети витрина не предназначена.

**Что произойдёт при переименовании региона в справочнике?** В расчёт берётся состояние TABLE_REGION_REF на момент запуска; повторный расчёт прошлого месяца после переименования даст новое название. Историческое название не сохраняется, это ожидаемое поведение.

**Можно ли получить агрегат по дням или по абонентам?** Нет: витрина месячная и обезличенная на уровне регион × тип сети; дневные и абонентские разрезы берутся из TABLE_DPI_RAW_PS.
