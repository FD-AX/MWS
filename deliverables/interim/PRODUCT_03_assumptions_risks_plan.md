## Риски и ограничения AI-решения

| Риск | Проявление у нас | Мера |
|---|---|---|
| Галлюцинация цитаты | модель «цитирует» то, чего нет в документе | программная верификация: цитата не найдена → находка отбрасывается (anchoring как метрика) |
| Фильтр режет правду | критик ставил 0 верным замечаниям по Data Catalog и кластеру Kafka (EXP-13) | официальные слоты и детерминированные проходы не подлежат порогу критика (EXP-14: 3/7 → 7/7) |
| Молчаливая потеря ответов | треть слотов чеклиста терялась из-за схемы ответа (EXP-13/14) | схема исправлена, невалидный ответ логируется, слоты добираются повторным вызовом, UNKNOWN на дашборде |
| Разброс модели между прогонами | GPT-5.5 ±2 дефекта на одном документе (EXP-04, EXP-14) | консенсус двух прогонов; числа в отчётах — диапазон/медиана |
| Ложные срабатывания на обезличивании | «как называется столбец FIELD_IMSI» у 120b | правило в промптах + score 0 в критике (EXP-16) |
| Шум на «не применимом» | вопрос про Kafka в документе без Kafka считался пробелом | исход NA у слота (EXP-16) |
| Длинные документы | обрыв полноты на ~28k символов (EXP-03) | чанкование по секциям — в плане; текущие документы МТС 3–6k |
| Слабая модель хуже думает «на два шага» | 120b пропускает выводные дефекты (по какому полю времени, что при ненайденном TAC) | зонды неоднозначности на 120b через vLLM (logprobs) — план |
| Синтетика не равна реальности | «шум» на чистой базе трижды оказывался реальными дефектами базы | вычитка сырых выводов глазами после каждого прогона, итерации it1–it7 |

## Принятые решения (продукт → техника)

1. **Конвейер вместо одного промпта.** Промпт-бейзлайн слеп к шаблону (0/6) и промахивает лёгкое; конвейер закрывает официальные пункты (EXP-10, EXP-14).
2. **Детерминированное ядро обязательно.** Ноль шума и гарантированные классы (шаблон, ссылки, фантомные поля) на любой модели (EXP-01, EXP-13).
3. **Неоднозначность меряется числом.** Семантическая энтропия и логит-зонд: единственные, кто ловит анафору; 16/16 на целевом документе (EXP-09, EXP-11, EXP-14).
4. **Модель — параметр, не архитектура.** Лестница Qwen-14B / gpt-oss-120b / GPT-5.5 на одном бенче; выбор модели заказчика — одна переменная (DIRECTION.md, EXP-15).
5. **Ничего не теряем.** Очередь с подтверждением после записи, DLQ, идемпотентность по хэшу документа, повтор при обрыве связи (проверено на 7-минутных заданиях).
6. **История — часть продукта.** Версии документа, все ревью и находки, обратная связь аналитика в Postgres; это же — данные для калибровки под заказчика.
