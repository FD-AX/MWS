# Метрики (привязка к MATRIX.md)

Принцип: бейзлайн = промпт-инжиниренная GPT-5.5 одним вызовом; каждая ступень
архитектуры добавляется только если двигает метрики. Все дельты — «было/стало».

## Лестница вариантов

| Вариант | Что добавлено | Что должен доказать |
|---|---|---|
| V0a | Наивный бейзлайн: «найди проблемы в ТЗ» | нижняя планка, демо-антипример |
| V0b | **Честный бейзлайн**: один вызов GPT-5.5 с матрицей дефектов в промпте, JSON-схемой и требованием цитат | сколько даёт чистый промпт-инжиниринг |
| V1 | + детерминированный слой (разделы, паттерны, C1-ссылки) | recall дешёвых классов = 1.0 при precision 1.0 |
| V2 | + чеклист слотов (батчи) + verify цитат | recall группы A ↑, anchoring = 1.0 |
| V3 | + критик (сравнительное ранжирование) + бюджет топ-N | precision ↑ при удержании recall |
| V4 | + GraphRLM-полнота (слот-граф, coverage) | recall A ↑ + число coverage для отчёта |
| V5 | + semantic entropy (--entropy) | ловит B9, которых нет у V0-V4 |

V0b обязан быть сильным (матрица в промпте, цитаты, JSON) — иначе дельты
архитектуры нечестные. V0a показываем только как иллюстрацию «generic-советов».

## Основные метрики

| Метрика | Что меряет | Как считается | Ground truth | Ориентир |
|---|---|---|---|---|
| **recall@gold** | долю найденных известных дефектов | матчинг находок против голд-листа (категория ИЛИ ключевые слова), разрез по группам матрицы A-F | голд-листы eval/gold_doc*.yaml (26 шт.) + подсаженные | ≥0.7 у V3+ |
| **precision (ручная)** | полезность находок | разметка каждой находки: fix / valid-minor / noise (шкала Bugbot) | ручная разметка команды | ≥0.6 в топ-7 |
| **anchoring rate** | заземлённость | % находок с верифицированной цитатой (программно, уже в пайплайне) | сам документ | 1.0 |
| **noise@clean** | шум | число находок severity≥medium на заведомо хорошем документе | исправленный doc3 / чистая синтетика | ≤1 |
| **coverage** | структурную полноту | закрытые слоты чеклиста X/19 | рубрика | отчётная, без порога |
| **findings budget** | лаконичность | находок на документ; % дублей | — | 5–8; дублей ~0 |
| **stability** | воспроизводимость | 3 прогона: % находок, повторившихся в ≥2/3 | сравнение прогонов | ≥0.7 (V0b обычно проседает — аргумент за пайплайн) |
| **cost/latency** | цену | токены и секунды на документ | лог клиента | отчётная |

## Разрез по группам матрицы

| Группа | Главная метрика | GT | Комментарий |
|---|---|---|---|
| A полнота | recall@gold(A) + coverage | голд + подсадка «удалить секцию» | заглушки обезличивания = слот закрыт |
| B однозначность | recall@gold(B); отдельно P/R на QuRE | голд + QuRE (2111 меток реального ревью) | entropy-калибровка: неоднозначные слоты должны ранжироваться выше |
| C ссылки | recall@gold(C), precision≈1.0 | голд + подсадка «сломать ссылку/поле» | витринный класс: C1 обязан ловиться детерминированно на 100% |
| D согласованность | recall@gold(D) + stability | голд + подсадка «внести противоречие» | класс, где V0b нестабилен между прогонами |
| E верифицируемость | в общем recall | голд | |
| F шаблон | recall = 1.0 у V1 | структура шаблона | детерминированный класс |

## Протокол

1. **Финализировать голд** (сейчас он черновой, моя разметка): ты + тиммейт
   независимо размечаете doc1-3 по кодам матрицы, расхождения разводит третий,
   считаем каппу. Без этого метрики плывут.
2. **Прогоны**: каждый вариант × {doc1, doc2, doc3, doc3-seeded, doc3-clean} × 3 раза.
3. **Матчинг находка↔голд**: v1 — автоматом (категории+ключевые слова,
   eval/run_eval.py), после первого прогона — ручной аудит матчинга (ключевые
   слова пересекаются между дефектами, автоматика завышает); для финального
   отчёта — LLM-judge сопоставляет, человек проверяет.
4. **Precision-разметка**: все находки лучшего варианта на doc1-3 размечаются
   командой (fix/minor/noise), 10 минут на документ.
5. Отчётная таблица в питч: варианты × метрики + разрез по группам. Отдельно
   дельта V0b→Vfinal — «архитектура добавляет к сильному промпту вот столько».

## Ограничения (честно фиксируем)

- Голд-лист = наша разметка, не кейсодателя; смягчаем тройной разметкой и каппой.
- Междокументные дефекты (G2-6) в single-doc recall не входят.
- QuRE/ReqEval — английский: меряют перенос языкового слоя, не доменного.
- Метрика кейса качественная — наши цифры это внутренняя валидация и материал
  для питча, не подмена оценки жюри.
