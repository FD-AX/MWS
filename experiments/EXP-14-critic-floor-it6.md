# EXP-14: критик не режет официальные пункты + добор слотов + база it6

Дата: 2026-09-03 (заведён до прогона) · Итерация синтетики: **it6** · Голды: v1 12 / v3official 13 / doc3 16.
Данные (после прогона): `eval/night/bench_exp14.md`, `eval/night/raw_exp14.json`, `eval/night/exp14.log`.

## Вопрос
Поднимут ли четыре фикса из диагностики EXP-13 recall официальных пунктов МТС на v3official,
не увеличив шум на чистой базе?

## Что изменилось (относительно EXP-13)
1. **Критик**: находки чеклиста по слотам с `official: true` (SER-01, CAT-01, NUL-03, FIL-02, LOC-02,
   LOC-03, REF-01, KEY-02) не подлежат порогу — пол = порог, дедупликация действует. В промпте критика
   правило: требования кейсодателя ≠ «бюрократия»/«другой документ». (EXP-13: CAT-01/FIL-02/LOC-02
   найдены чеклистом и срезаны со score 0.0.)
2. **Чеклист**: слоты без ответа в батче добираются отдельным вызовом (EXP-13: 10/27 UNKNOWN молча).
3. **Вопросы слотов МТС** уточнены: заглушка засчитывается только в позиции слота (топик без кластера,
   «в HDFS кластера X» без пути, «по умолчанию» для формата, обещание карточки Data Catalog = не указано);
   REF-01: «не применимо» допустимо только без джойнов со справочниками.
4. **Верификация цитат**: вторая ступень без «|» и переносов (табличные цитаты; EXP-13: 5/21 отброшены).
5. **База it6**: ~10 реальных дефектов чистой базы закрыты (см. EXP-13 «Вычитка шума»).
6. **Схема ответа чеклиста** (найдено при первом старте EXP-14, прогон остановлен и перезапущен): на OK-ответах
   модель отдаёт `"why": null, "ask": null`, а поля были объявлены `str` → pydantic отвергал ответ, код молча
   его выбрасывал → слот UNKNOWN. Терялись именно **OK-статусы**, а по ним работают энтропия (v2e) и логит-зонд
   (v2l) — они опрашивают только OK-слоты. Фикс: `Optional[str]`, невалидный ответ логируется. Ожидание
   расширено: **v2e/v2l должны заметно вырасти** относительно EXP-13 (там зонды пропускали до 10 слотов).

## Выводы
1. **Все три дыры EXP-13 закрыты и доказаны прогоном**: пункты МТС на v3official с 3/7 до 7/7 у всех
   вариантов; UNKNOWN 0; v2e/v2l на doc3 16/16 при anchoring 96–100%.
2. **Прод-вариант демо на GPT: v2e или v2l** (равны по recall: 12/13, 16/16, 7/8; v2e лучше на synth_v1
   10/12, v2l дешевле ×10 и anchoring 100%). Ансамбль v2e+v2l не нужен — пересечение почти полное.
3. **Разброс GPT ±2** сохраняется (EXP-04) → для чисел в отчёте брать медиану двух прогонов.
4. Остаток шума на чистой it6-базе — снова наполовину правда (NO_REGION «отброшенные» vs остаётся в витрине;
   порядок дедупликации и отбраковки NULL-ключей; HDFS-пути источников; DDL без NOT NULL при NOT NULL в
   структуре; DAG_BACKFILL не в исходниках) → **it7**. Правило «читать шум глазами» работает третий раз подряд.
5. Оставшиеся слепые зоны — детерминированные задачи: SYN-C-SECREF (ссылка «раздел N» при ненумерованных
   заголовках — считать разделы по порядку), HRD-RET (сверка 36 мес при ретеншене 24 — межсекционное число).
