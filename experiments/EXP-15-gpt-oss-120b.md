# EXP-15: gpt-oss-120b (self-hosted, ярус заказчика) на том же конвейере — разрыв с GPT-5.5

Дата: 2026-09-03 (заведён до прогона) · Ветка: `infra/oss-120b` · Итерация синтетики: it6 · Голды: targets_key (v1 12 / doc3 16 / v2hard 8 / v3official 13 + clean).
Данные (после прогона): `eval/night/bench_exp15.md`, `eval/night/raw_exp15.json`, `eval/night/exp15.log`.

## Вопрос
Сколько теряет конвейер при замене GPT-5.5 на открытую gpt-oss-120b (MoE 117B/5B активных, MXFP4),
и какие классы дефектов страдают первыми? Это точка отсчёта для задачи «нивелировать размер модели
архитектурой» (цель юзера: на 120b выбить столько же, сколько на 5.5).

## Конфигурация
- Модель: `gpt-oss:120b` через ollama на RunPod H100 80GB ($3.49/ч), `OLLAMA_CONTEXT_LENGTH=32768`,
  `OLLAMA_NUM_PARALLEL=4`; endpoint `https://<pod>-11434.proxy.runpod.net/v1` (бэкенд `pod`).
- Клиент: `TZR_MAX_TOKENS=4096` (пол бюджета: reasoning считается в max_tokens),
  `TZR_REASONING_EFFORT=medium` (смоук: medium ≈ 100–140 completion-токенов на короткий JSON, low ≈ 52).
- Варианты: `v1g` (пол), `v2g` (конвейер + граф, критик с защищёнными слотами, добор слотов, схема OK/null).
  `v2l` невозможен: ollama не отдаёт logprobs (→ vLLM в compose-контуре). `v2e` — отдельным прогоном
  (сэмплы на той же модели).
- Цели: `eval/targets_key.yaml`. Сравнение: EXP-14 (те же фиксы, GPT-5.5) — единственный честный референс.

## Рычаги «нивелировать размер» (после точки отсчёта, по одному, каждый = строка бенча)
1. `reasoning_effort=high` (цена: время) vs `low` (цена: качество) — где оптимум.
2. Чанкование по секциям для чеклиста/doc-level (EXP-03: обрыв на ~28k; для 120b порог может быть ниже).
3. Консенсус ×2 прогонов (EXP-04: у GPT разброс 11/11↔7/13; у детерминированного t=0 3/3).
4. Калибровка промптов/порога критика под модель на фабрике синтетики (H11), few-shot из голдов.
5. Больше детерминированных слоёв (G2-3, G2-7, анафора) — они модели не видят.
6. vLLM вместо ollama → logprobs → v2l (B-класс 9/9 на GPT) и EXP-12 перплексия.

## Результат (прогон 22:41–23:2x, 10/10 строк без ERROR; UNKNOWN-слотов 0)

Инфра-факты по дороге: gpt-oss:120b через ollama падал с «CUDA error: the function failed to launch» на
промптах >~1k токенов → производная модель `gpt-oss-120b-b64` (`num_batch 64`, создана через /api/create,
без перекачки весов); reasoning считается в max_tokens → пол 4096 и `reasoning_effort=medium`;
сырые переносы строк в цитатах → `strict=False`; обрезанный JSON → повтор с удвоенным бюджетом.
Канарейка: c1/c2 ✓, c3 (чистый) — 5 high + 6 medium (порог 0 для GPT; для 120b гейт смягчён, шум меряет бенч).

| Цель | **120b v2g** | GPT-5.5 v2g (EXP-14, прогон 1 / 2) | GPT-5.5 v2e | GPT-5.5 v2l |
|---|---|---|---|---|
| synth_v1 | **9/12** | 7/12 / 9/12 | 10/12 | 7/12 |
| doc3 (целевой) | **12/16** (в контуре, другой прогон: 14/16) | 14/16 / 16/16 | 16/16 | 16/16 |
| synth_v2hard | **7/8** | 7/8 / — | 7/8 | 7/8 |
| synth_v3official | **11/13** (A 6/7) | 12/13 (A 7/7) / — | 12/13 | 12/13 |
| шум@clean (it6) | **11** | 9 / — | 7 | 7 |
| anchoring doc3 | 87% | 83% / 100% | 96% | 100% |
| время/документ | ~7 мин (H100, ollama, слоты делились с бенчем) | ~4–5 мин | | |

Промахи 120b на doc3: **G3-4** (по какому полю времени «последний IMEI»), **G3-6** (TAC не найден →
vendor?), **G3-7** (бэкфилл не описан), **G3-8** (UTC vs региональные пояса) — все четыре «выводные»
дефекты классов B9/A3/A7/D3, где нужно домыслить следствие; GPT берёт их зондами (v2e/v2l 16/16).
На v3official промах A-класса один: OFF-REF («не применимо» у справочников при джойне в алгоритме).
Шум на чистой базе (11): половина — слоты, которым нужен статус «не применимо» (LOC-02/LOC-03 при
отсутствии Kafka/HDFS в документе, INC-01 при полной перезаписи), остальное — dev_question без
конкретики (критик на 120b мягче).

Слепые зоны 120b+v1g (10): G3-4/6/7/8, SYN-A-BCKF, **SYN-B-ANAPH** (анафора — как у всех без логитов),
SYN-E-MEAS, HRD-RET, OFF-FAQ, OFF-REF.

## Выводы
1. **Разрыв 120b ↔ 5.5 на том же конвейере: 0–1 дефект на официальных пунктах МТС (v3official 11 vs 12),
   2–4 дефекта на целевом документе (doc3 12–14 vs 14–16), шум +2…+4.** Это точка отсчёта; на synth_v1 и
   v2hard разрыва нет.
2. Что теряется — не «знание», а **выводные неоднозначности** (B9/A3/A7/D3): именно их у GPT добирают
   энтропия и логит-зонд. Значит, первый рычаг для «нивелировать размер» — **vLLM вместо ollama → logprobs →
   v2l на 120b** (у GPT v2l даёт doc3 16/16, B-класс 9/9), второй — энтропия на той же модели (v2e, 4 слота).
3. **Слоты «не применимо»**: рубрике нужен третий исход N/A (нет Kafka → LOC-02 не MISSING) — уберёт ~половину
   шума на 120b и часть на GPT. Дешёвый фикс промпта чеклиста + схемы.
4. **reasoning_effort**: medium даёт ~7 мин/документ; проверить high (качество) и low (скорость) как строки
   бенча — открыто.
5. Инфраструктурно 120b годен для демо и контура заказчика: сквозной сценарий (PDF → очередь → воркер →
   отчёт → история в Postgres) прошёл на нём; цена H100 $3.49/ч ≈ $0.4/документ при 7 мин.
