# EXP-13: синтетика it5 в официальном шаблоне МТС + пересчёт матрицы ошибок

Дата: 2026-09-03 · Итерация синтетики: **it5** · Голды: doc 12/8/16, synth v1 12 / v2hard 8 / **v3official 13** = 69 дефектов.
Данные: `eval/night/bench_exp13.md`, сырые: `eval/night/raw_exp13.json`, лог: `eval/night/exp13.log`,
матрица: `eval/error_matrix.md`. Офлайн-пол: `eval/night/bench_it5_offline_v1g.md`.

## Вопрос
1. Как варианты распределяются по классам ошибок на синтетике, построенной по **официальному
   шаблону МТС** (20 разделов) с инъекциями по **8 «Основным моментам»** (v3official)?
2. Три способа мерить неоднозначность на одном конвейере: ничего (v2g) vs сэмплирование (v2e)
   vs логит-зонд (v2l, EXP-11) — recall B-класса и шум при разной цене.
3. Держатся ли числа реальных доков (doc1–3) после починки пустых ответов LLM-клиента
   (EXP-10: v2g ERROR ×2, EXP-11: v2l ERROR ×2 — «В ответе модели нет JSON: ''»).

## Что изменилось в it5 (почему цифры не сравниваются с it4 напрямую)
- Новая чистая база `synth/base/mart_traffic_official_clean.md`: **17 183 симв.** против 6 100 у it4
  (все 20 разделов шаблона заполнены содержательно: Data Catalog, сериализация, кластер Kafka
  источника, полный HDFS-путь, NOT NULL/NULLABLE по каждому полю, типовые фильтры, перечень
  справочников, пример данных на 10 строк, DDL, FAQ, история изменений).
- Рецепты v1 и v2hard **перенесены на новую базу** без изменения инъекций (кроме ссылки на
  раздел: 12 → 31, чтобы ссылка осталась битой при 24 разделах); все find-строки уникальны.
- Новый рецепт **v3official**: 13 инъекций — 8 по пунктам МТС (SER/CAT/NUL-03/FIL-02/шаблон ×2/
  LOC-02/LOC-03/REF-01) + 4 межсекционных, возможных только в полном шаблоне (DDL ≠ структура,
  пример данных вне домена, история изменений с полем-фантомом, FAQ против алгоритма).
- Фабрика: `edits` — несколько правок на один дефект (факт продублирован в таблице и DDL).
- Детерминированный слой: пустой официальный раздел без «не применимо» → `template:empty_section`.
- LLM-клиент: пустой ответ = сбой → ретрай (×4, jitter, ×2 бюджет при finish_reason=length).
- Бенч пишет построчный прогресс в stderr (лог виден во время прогона).

## Ожидание (до прогона)
| Что | Ожидание | Почему |
|---|---|---|
| v1g clean | шум **0** (измерено офлайн) | база проверена детерминированным слоем перед прогоном |
| v1g v3official | **3/13** (измерено офлайн): OFF-TPL, OFF-EMPTY, OFF-HIST | ровно детерминируемые классы F/C |
| v2e_gpt doc3 | ≈ **14/16** (как в EXP-10) | документ и голд не менялись |
| v2e_gpt v3official | **9–11/13**; промахи: OFF-EXAMPLE (5G, expert), вероятно OFF-DDL и OFF-FAQ | слоты SER/CAT/NUL/FIL/LOC/REF есть в рубрике; межсекционные D-дефекты — слабое место (EXP-10: D 11/13) |
| v0b_gpt v3official | ниже v2e на F-классе (0/2) и слотах МТС | промпт слеп к официальному шаблону (EXP-10: F 0/4) |
| synth_v1 (LLM) | **−1…−2** к EXP-10 (v0b 11/12, v2e 10/12) | документ втрое длиннее (EXP-03: recall падает с длиной, A-класс первым) |
| шум@clean (LLM) | выше it4 (11–15 → 12–18) | больше поверхности для «лишних» замечаний; цель после калибровки ≤10 |
| v2l vs v2e | B-класс ≈, шум ≤, цена ~×0.1 | EXP-11 смоук 4/4; логиты детерминированы |
| ERROR-строк | **0** | ретрай пустого ответа |

## Конфигурация
Варианты: `v1g, v0b_gpt, v2g_gpt, v2e_gpt, v2l_gpt`; цели: `eval/targets.yaml` (7: synth_v1, doc3, doc2,
doc1, v2hard, v3official, clean). Модели: gpt-5.5 (основные проходы + критик), gpt-5.4-mini
(энтропия), gpt-4.1-mini (логиты). Рубрика официальная (27 слотов). VPN проверен (NL) перед стартом.
