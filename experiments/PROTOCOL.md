# Протокол измерений (заморожен 2026-09-05, действует до финала 07.09)

> **Решение 05.09 05:25 (Леонид): основная и единственная модель проекта — self-hosted gpt-oss-120b.**
> GPT-5.5 больше не гоняется и не считается «мейном»: у заказчика облачной frontier-модели не будет. Уже сделанные
> прогоны GPT (EXP-14…19, `eval/night/m3_gpt_key.log`: v2g ×2 повтора, v2e частично) остаются **справочным потолком**
> в таблицах — как ориентир, чего достигает облачная модель на том же коде, не как цель сравнения.
> Критерий п.5 читается как абсолютные цели для 120b: doc3 ≥ 15/16, v3official ≥ 12/13, шум@clean ≤ 8, precision ≥ 95 %.

Зачем: до этого момента у GPT-5.5 и gpt-oss-120b были разные наборы архитектур, разные реализации одного и того же
сигнала (энтропия дешёвой моделью vs той же; зонд по логитам vs Монте-Карло) и разные имена вариантов. Эффекты
рычагов (+1…+2 дефекта) сравнимы с разбросом одиночных прогонов. Отсюда правила ниже.

## 1. Что заморожено
- Синтетика **it7**, голды doc1 12 / doc2 8 / doc3 16, `eval/targets_key.yaml` + `eval/targets_docs.yaml`.
- Рубрика `rubric.yaml` (27 слотов, правила применимости EXP-18) и `rubric_extra.yaml` (4 слота EXP-19).
- Промпты, порог критика θ=4, фильтры EXP-18.
- До финала меняется только код под тестами. Любое изменение базы/голда/рубрики = новая итерация и новая таблица.

## 2. Канонические архитектуры (одни и те же для всех моделей)
| Имя | Состав | Сигналы |
|---|---|---|
| `v1g` | детерминированный слой + граф сущностей | без LLM |
| `v2g` | + чеклист, документ-уровень, взгляд разработчика, верификация цитат, критик | LLM |
| `v2e` | v2g + semantic entropy (5 сэмплов **той же** модели на OK-слот) | LLM |
| `v2s` | v2g + зонд неоднозначности **Монте-Карло** (8 коротких ответов при t=1 на OK-слот) | LLM |
| `v2x` | v2g + общие слоты `rubric_extra.yaml` | LLM |
| `v2f` | v2g + энтропия + зонд + общие слоты (кандидат в прод) | LLM |

Модель задаётся флагом, не именем варианта: `--backend openai` (GPT-5.5) или `--backend pod` (gpt-oss-120b на vLLM).
Легаси-варианты `*_gpt`, `v2l*`, `v2el*` остаются только для воспроизведения старых EXP; в новые таблицы не входят.
Зонд по логитам (`v2l_gpt`, gpt-4.1-mini) — историческая строка: reasoning-модели логиты не отдают (EXP-19).

## 3. Повторы и чтение эффектов
- Каждая пара вариант×цель гоняется **≥2 раз** (`--repeat 2`, для итоговых конфигураций 3); в таблицу идёт
  медиана и размах. `eval/matrix.py` собирает матрицу из сырых JSON.
- Эффект рычага = разность медиан соседних строк; если он меньше размаха любой из строк — пишем «не обнаружен».
- Прогоны на поде — последовательно в одном процессе на модель (параллельные процессы допустимы только для разных
  моделей).

## 4. Полнота и точность
- Recall по голду считается только на голд-целях; «лишние» ≠ ложные.
- Точность — только по разметке лишних: **слепая** (находки обеих моделей перемешаны, модель скрыта до конца разметки),
  классы TP / FP / NA + класс мусора; выборка ≥30 на вторую разметку другому участнику, отчитывается согласие.
- Для каждого промаха по голду — ручная проверка, нет ли покрывающей находки другой формулировки; отдельно
  отчитывается «recall с поправкой на матчер».
- Общие слоты `rubric_extra.yaml` калиброваны на doc3 → их вклад оценивается по doc1/doc2/synth, doc3 для них
  помечается «in-sample».

## 5. Критерий «уравняли 120b с GPT-5.5» (записан до прогона)
По медианам ≥2 прогонов на it7: 120b в лучшей канонической конфигурации в пределах **1 дефекта** от GPT-5.5 в лучшей
конфигурации на doc3 и v3official, шум@clean не выше GPT, точность по слепой разметке ≥95 %. Не дотянули — так и пишем,
с указанием, какой класс дефектов остаётся за GPT.

## 5a. Слабые места измерений (записаны 05.09 07:15 — читать перед любой цифрой из таблиц)
1. **Точность размечена одним человеком** — тем же, кто пишет правила отсечения. Precision 80–85 % (m4) — верхняя оценка
   одного суждения, не факт. Пакет для второй разметки готов (`eval/labels/m4_blind.yaml` без ключа); согласие не измерено.
2. **«Чистая» база чиста по построению**: все вопросы разработчика на clean размечены как мусор без проверки каждого по тексту;
   часть может быть реальными дефектами базы. Шум@clean — оценка сверху для шума и вниз для «истинности» правил.
   База it6/it7 вычищалась по находкам моделей → шум на ней оптимистичнее, чем на незнакомом документе.
3. **Матчер по ключевым словам хрупок**: в матрице m4 из 414 попаданий по голду 56 % держатся на одной находке, 29 % — на
   одном ключе, **16 % — на одной находке и одном ключе** (v2g 17 %, v2f 13 %). Ключи G3-4/G3-6 расширены после просмотра
   промахов (v2) — это документированное вмешательство в голд, применённое ко всем прогонам одинаково.
4. **Два повтора**: медиана двух = среднее; эффект меньше суммарного размаха — «не обнаружен». По Σ/49: v2g 35–41 (мед. 38);
   **v2x 38–43 (40.5) — прирост в пределах размаха, не обнаружен**; v2e/v2s 42 (+4, на границе); v2f 44–45 (+6.5, за пределами
   размаха — единственный надёжный прирост полноты, и он куплен шумом 12.5 и precision 63 %).
5. **Критерий п.5 не выполнен** ни одним вариантом на 05.09 07:15: precision ≥ 95 % нет (лучшее 85 %), шум ≤ 8 нет (лучшее 9).
   Полнота цели достигает (doc3 15–16/16, v3official 12–13/13).
6. `--det` добавляет детерминированные находки постфактум (правило ссылок по имени) — помечено в каждой таблице.
7. Справочные строки GPT-5.5 — одиночные/частичные прогоны другого времени; сравнивать с ними можно только направление.
8. Шум@clean считает находки medium+; advisory/low не входят. Precision считается после верификации цитат (отброшенные
   не в знаменателе) и после критика.

## 6. Команды
```
# 120b (pod) и GPT-5.5 (openai): одинаковый набор, по 2 повтора
python eval/bench.py --backend pod    --variants v2g,v2e,v2s,v2x,v2f --repeat 2 --targets eval/targets_key.yaml  --out eval/night/m_pod_key.md  --json eval/night/m_pod_key.json
python eval/bench.py --backend openai --variants v2g,v2e,v2s,v2x,v2f --repeat 2 --targets eval/targets_key.yaml  --out eval/night/m_gpt_key.md  --json eval/night/m_gpt_key.json
python eval/matrix.py eval/night/m_pod_key.json eval/night/m_gpt_key.json --out eval/night/matrix_key.md
```
