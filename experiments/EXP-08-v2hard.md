# EXP-08: жёсткий набор v2hard (насыщение бенча)

Дата: 2026-09-03 · Рецепт: `synth/recipes/mart_traffic_v2hard.yaml` ·
Данные: `eval/night/bench_gpt_v2e.md`.

## Вопрос
Голд doc3 насыщен (11/11 у GPT) — различает ли сильнейших набор из 8
экспертных логических инъекций в текстуре документов МТС?

Каждая инъекция обоснована родственным дефектом их доков: граница месяца ← G3-8,
невыполнимое время/ретеншен-противоречие ← G3-1, пустышка «в установленном
порядке» ← их «fallback-логика (см. алгоритм)», ссылка на именованный раздел ←
их стиль ссылок, перегрузка категории UNKNOWN ← их термин-дрейф.

## Результат

| Слой/вариант | recall v2hard |
|---|---|
| Детерминированный (v1g) | 0/8 (by design) |
| v2g_gpt | **8/8** (все 4 expert) |
| v2e_gpt | 7/8 |

## Выводы
1. v2hard отделяет модели (Qwen будет низко) и слои, но **внутри GPT-вариантов
   различают уже только шум и стабильность** — потолок для GPT+конвейер.
2. Для дальнейшей дифференциации сильнейших нужен v3hard: мульти-hop дефекты
   через 2–3 таблицы/раздела (зарегистрировать как отдельный эксперимент).
3. Три из пяти «лишних» на v2hard — легитимные тонкие замечания (расположение
   LOG-таблицы; сверка суммы байтов невозможна из витрины после деления) —
   кандидаты в голд v2hard.
