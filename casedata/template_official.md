# Шаблон документации «Потоковые данные/витрины» (официально от МТС, Drive 2026-09-01)

Источник: «Шаблоны документации.pdf» (папка кейса, ID 19RMT35CQujZNWm5muOKcyE5H67xMmVHe).
Структура разделов (порядок сохранён):

1. **Общие сведения** — краткое описание потока данных
2. **Решаемая проблема** — причины создания, задачи
3. **Продуктовые метрики** — метрики, которые изменятся
4. **Заказчики** — продукт/подразделение-заказчик
5. **Нефункциональные требования** — например: объём данных, задержки
6. **Системы-источники** — перечень и краткое описание
7. **Data Catalog** — ссылка
8. **Исходники проекта** — ссылка на GitLab
9. **Команда** — аналитик, разработчик (ФИО)
10. **JIRA**
11. **Источники данных** — описание, тип источника, ссылка на источник, **сериализация**
12. **Источники обогащения данных** — описание, ссылка
13. **Приёмники данных** — описание, **кластер**, ссылка на каталог, **сериализация**
14. **Схема потоков данных**
15. **Алгоритм обработки потока** — пошагово: Шаг 1 Фильтрация (условия), Шаг 2
    Обогащение, Шаг N …; **формирование ключа (kafka) / партиции (hdfs)**
16. **Структура данных** — приёмники: атрибут/тип/описание/комментарий;
    источники: источник/атрибут/тип
17. **Пример данных** — 10 строк из таблицы (под спойлером)
18. **DDL** — схема таблицы
19. **FAQ** — нюансы витрины, неочевидные бизнес-пользователям
20. **История изменений**

Правило кейсодателя (из «Основных моментов», п.5): все разделы шаблона сохраняются;
неиспользуемый этап — явная формулировка «не применимо».

Наблюдение: тестовые документы кейса сами нарушают шаблон (в doc1-3 нет Data
Catalog, DDL, примеров данных, истории изменений) — детерминированная проверка
разделов по официальному шаблону даёт бесспорные находки.
