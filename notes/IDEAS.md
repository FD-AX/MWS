# Гипотезы для реализации (сверх GraphRLM-полноты и semantic entropy)

Каждая: механика → как проверить числом (на голде/синтетике) → ожидание/риск.

## Детерминированные (дёшево, precision ~1.0)

### H1. Граф сущностей из заглушек анонимизации ⭐
Обезличивание МТС нам подарок: все сущности уже помечены (TABLE_*, FIELD_*,
TOPIC_*, SCHEMA_*, DAG_*). Regex-экстракция упоминаний → граф «где определено /
где используется» → детерминированные проверки: поле в алгоритме без описания
в структурах (C2), таблица упомянута, но не объявлена (C4/D1-дрейф имени),
описано, но не используется (C6). На doc3 это ловит G3-2 БЕЗ LLM.
Проверка: recall C-класса на голде и synth (SYN-C-DANGLE, SYN-D-NAME).
Риск: на реальных (необезличенных) доках нужен NER — но тест хакатона будет
на обезличенных.

### H2. Структурный парсер таблиц
Маппинги/структуры = таблицы (главная боль LLM по Fujitsu-кейсу). Парсим
markdown-таблицы в фреймы → проверки: пустая ячейка «Источник/Правило» (A12),
нет колонки типов (F3), тип без длины, поле из колонки «Правило» отсутствует
в источниках (вместе с H1). Проверка: A12/F3 на синтетике с испорченными таблицами.

### H3. Проверка внутренних ссылок
«см. раздел N / приложение X» против фактической структуры документа (C1),
«и в таблице выше/ниже» без таблицы. Простой парсер. Ловит SYN-C-SECREF.

### H4. Размерностный анализ формул
Парсим формулы из колонки «Правило» (sum(bytes)/1024^3 → ГБ ок; счётчик/счётчик
→ доля; % без ×100). Ловит E2 и ошибки типа «GB, а делим на 1e6».
Проверка: подсадить ошибку единиц в synth v2. Риск: формул мало — узкая фича.

## LLM-гипотезы

### H5. «Компиляция ТЗ»: генерация кода с журналом допущений ⭐
Просим модель написать псевдокод/SQL пайплайна по ТЗ и ОБЯЗАТЕЛЬНО логировать
каждое допущение: «assumption: инкремент по FIELD_X, в ТЗ не указано».
Список допущений = находки. Сильная демо: «мы скомпилировали ваше ТЗ — вот где
компилятор гадал». Проверка: допущения на doc3 против голда (ожидание: ловит
G3-3, G3-4, G3-6 — классы, где чеклист слепой, потому что вопрос не из рубрики).

### H6. Дифф двух реализаций (implementation-level entropy) ⭐
Развитие H5 + твоей энтропии: генерим реализацию ДВАЖДЫ (t≈0.8), диффим не текст,
а решения (поля, джойны, условия). Точки расхождения = неоднозначности уровня
логики, которых не видно на уровне ответов на вопросы. Проверка: расхождения
против B/D-классов голда. Риск: дифф решений надо структурировать (json-контракт
реализации), иначе сравнивать нечего.

### H7. Персона тестировщика: генерация тест-кейсов как детектор
Кейс сам говорит «от лица аналитика, разработчика ИЛИ тестировщика». Просим
сгенерить тест-кейсы по ТЗ; каждый тест, для которого нельзя определить expected
result, = находка E1 (неверифицируемость). Бонус: сами тест-кейсы — вторая
демо-фича бесплатно (Jama так продаёт Advisor). Проверка: доля «недописуемых»
тестов против E/A-классов голда.

### H8. QA-coverage: вопросы из самого документа
Отличие от чеклиста (вопросы фиксированные): генерим вопросы ИЗ документа
(«чему равен FIELD_CELL_GEN для 3G?», «какой регион у кода вне справочника?») и
проверяем отвечаемость по тексту. Ловит дыры, специфичные для документа, которых
нет в рубрике. Проверка: новые находки сверх чеклиста на голде (дельта recall).

### H9. Контрастное ревью против эталона
Retrieval ближайшей «хорошей» секции (наши чистые базы, data contracts) →
«чем текущая секция беднее эталона?». Проверка: дельта recall A-класса поверх
чеклиста. Риск: шум «у вас нет X» там, где X не нужен — фильтровать критиком.

### H10. Logprobs вместо сэмплинга
Если бэкенд отдаёт logprobs: уверенность ответа на вопрос чеклиста за 1 вызов
вместо N сэмплов энтропии. Проверка: корреляция logprob-уверенности с B-классом
голда vs энтропия (та же метрика, 5x дешевле). Риск: у API-моделей logprobs
часто нет — тогда только локально.

## Мета (усилители всего)

### H11. Авто-калибровка промптов на фабрике синтетики ⭐
Фабрика даёт (документ, голд) бесконечно → промпт-варианты оцениваются
recall/precision автоматически, hill-climb без ручного «кажется, лучше»
(mini-DSPy). ВАЖНО: только на train-рецептах (v2+), тест v1 не трогаем.
Проверка: дельта V2-промпта после 5-10 итераций калибровки.

### H12. Севрити через blast radius
Критик оценивает не «важность», а «что случится при неверной догадке»:
тихая порча данных > падение джобы > переспрос > стиль. Заземляет севрити
в последствия, меньше споров на разметке. Проверка: согласие севрити с ручной
разметкой команды до/после.

## Порядок пробы (рекомендация)

1. **H1+H2+H3 пакетом** — детерминированный граф документа: дёшево, precision 1.0,
   закрывает C-класс целиком и куски A; это же фундамент под GraphRLM-слоты.
2. **H5/H6** — компиляция с допущениями: самая яркая новая LLM-гипотеза,
   дополняет чеклист там, где рубрика слепа.
3. **H11** — включить, как только есть креды: превращает фабрику из «мерилки»
   в «улучшалку».
H7 — если останется время (даёт вторую демо-фичу почти бесплатно).
